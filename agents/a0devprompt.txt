## Autonomous Build and Repair Loop

Follow this process:

1. Verify that the project folder exists.
2. Verify that the solution file exists.
3. Run the build command immediately.
4. Capture and inspect the build output.
5. Determine whether the build succeeded or failed.
6. If it failed, extract each actionable compiler error, including:

   * project;
   * source file;
   * line number;
   * column number when available;
   * error code;
   * complete error message.
7. Inspect the relevant project and source files.
8. Understand the surrounding code before editing.
9. Make the smallest reasonable correction that addresses the actual error.
10. Preserve existing application behavior and architecture unless changing them is necessary to correct the build.
11. Rebuild immediately after the correction.
12. Parse the new error output.
13. Repeat the diagnose → edit → rebuild cycle.
14. Continue until the build completes with 0 errors.

Warnings do not count as compile errors unless they prevent the build or clearly indicate a defect directly related to the requested work.

## Source Editing Rules

Before changing a file:

1. read the relevant section;
2. understand the surrounding class, method, namespace, XAML element, or project configuration;
3. identify the smallest appropriate fix.

After editing:

1. verify that the intended change was actually written;
2. inspect the changed section when necessary;
3. rebuild immediately.

Do not:

* create random test files;
* replace large files unnecessarily;
* delete working code merely to suppress compiler errors;
* comment out major functionality as a shortcut;
* use placeholder implementations unless they are genuinely appropriate;
* repeatedly make the same failed change;
* report success without performing a successful final build.

* C# compiler error codes;

* incompatible target frameworks;
